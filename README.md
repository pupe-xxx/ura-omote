# URA OMOTE

青と橙の2つの駒を、同時に同じ向きへ動かして、それぞれのゴールへ届けるパズル。ブラウザで動く。TypeScript + Vite + Canvas。
[web-game-template](https://github.com/pupe-xxx/web-game-template) から作った。STRATA の「表を盛ると裏が掘れる」という膜のルールを、1人用のパズルに切り出したもの。

## 遊び方

- 下の矢印をタップすると、青と橙が**同時に同じ向きへ**1歩動く
- マスの色は、そのマスで止まれる駒の色を表す。**同じ色のマスは壁（入れずに止まる）、違う色のマスは入ると落ちる**

| マス | 青の駒 | 橙の駒 |
|---|---|---|
| 青いマス | 止まる | 落ちる |
| 橙のマス | 落ちる | 止まる |
| 灰色の壁 | 止まる | 止まる |
| 黒い穴 | 落ちる | 落ちる |
| まわりの壁（盤を囲む灰色） | 止まる | 止まる |
| まわりの壁が無い所 | 外へ落ちる | 外へ落ちる |

- 片方だけ止まると、2つの位置がずれる。これを使ってゴールに合わせる
- 2つは別の面にいるので、同じマスに重なれる
- ステージによっては、マスを**青にする・橙にする**ことができる。回数に限りがあり、1手として数える。平らなマスは選んだ色になり、反対の色のマスは平らに戻る。駒のいるマス・ゴールのマス・壁・穴は変えられない
- 青が青の輪に、橙が橙の輪に、同時に入っているとクリア
- 手数が最少なら ★3、2手多くまでは ★2、4手多くまでは ★1。それでも届かないか、どちらかが落ちると失敗

ステージは26個。遊び方を覚えるステージが6つあり、新しい仕掛けはそれを覚えるステージの後に出てくる。

| ステージ | 出てくるもの |
|---|---|
| 1〜4 | 遊び方を覚える（動かす・青いマス・橙のマス・マスを変える） |
| 5〜10 | 青いマスと橙のマスだけ |
| 11 | 遊び方を覚える（灰色の壁と黒い穴） |
| 12〜18 | 壁と穴が出る |
| 19 | 遊び方を覚える（まわりの壁が無い所） |
| 20〜23 | まわりの壁が一部無い |
| 24〜26 | まわりの壁が全部無い |

クリアした一番先のステージの、2つ先まで遊べる。

## コマンド

| コマンド | すること |
|---|---|
| `npm run dev` | 手元で動かす |
| `npm test` | ルールの自動テスト。全ステージが解けることと、★3 の手数が最少であることも確かめる |
| `npm run check` | 全ステージを解いて、最少の手数と、かかった時間を出す |
| `npm run gen` | ステージを作り直す（`src/game/levels.gen.ts` を書き出す）。1分ほど |
| `npm run record` | 動作記録（`tests/golden/golden.json`）を取り直す |
| `npm run typecheck` | 型の検査（ルール側が画面に触れていないかも見る） |
| `npm run build` | 検査してから `dist/` に公開用のファイルを作る |

## フォルダ

```
src/
  main.ts    入口
  kit/       どのゲームでも使う共通部分（型のまま）
  game/      ルール。画面の処理に触れない
    hex.ts         六角形の盤の座標
    rules.ts       動かす・マスを変える・クリアと失敗の判定・星の数
    solve.ts       総当たりで最少の手数を求める
    levels.ts      ステージの一覧。遊び方を覚えるステージ（手作り）と、作ったステージの並べ方
    levels.gen.ts  scripts/gen.ts が書き出したステージ（段階ごと）
  ui/        描画と操作
    shell.ts       ステージ選択・結果・星の保存（ステージ制のパズルに共通の外枠）
    game.ts        このゲームの盤と方向ボタンの描画、タップの処理
    hexview.ts     六角形の盤を描くための座標の計算
    i18n.ts        日本語と英語の切り替え（ブラウザの言語で決まる）
scripts/
  gen.ts     ステージを作る
  check.ts   全ステージを解いて確かめる
  record.ts  動作記録を取り直す
tests/
```

`src/ui/shell.ts`・`hexview.ts`・`i18n.ts`・`style.css` は、ROLLER BREAK と同じもの。`src/game/hex.ts` は、盤のまわりの輪（`rimCells`）を足してある。

## ルールの持ち方

- 青いマスと橙のマスは、1つの数（高さ）で持つ。1 が青、-1 が橙。元は「表から見た山は、裏から見ると穴」という膜で、青は表、橙は裏を歩く。青は高さをそのまま、橙は逆に見て、自分から見て高ければ壁、低ければ穴になる
- 「青にする」は高さを1上げ、「橙にする」は1下げる。だから反対の色のマスに使うと平らに戻る
- 灰色の壁・黒い穴・まわりの壁が無い所は、高さとは別に持つ
- まわりの壁は、盤のすぐ外の輪（半径 + 1）。壁が無いマスだけを `open` に並べる

## ステージの作り方

`scripts/gen.ts` が、乱数で盤を作り、総当たりで解いて、次の条件を満たすものだけ残す。乱数の種は固定なので、何度実行しても同じステージができる。

- 解ける。最少の手数が、その段階の範囲に入っている
- 2つの駒からゴールまでのずれが違う（同じだと、並んで歩くだけで着く）
- マスを変えられるステージは、変える回数を1つ減らすと最少では解けない
- まわりの壁が無い所があるステージは、全部壁にした時と最少の手数が違う（開いている所が効いている）

まわりの壁は、ばらばらにではなく、続いた区間をまとめて無くす（どこが開いているか見て分かるように）。

段階は `scripts/gen.ts` の `TIERS` にある。`src/game/levels.ts` が段階の番号でステージを並べているので、段階を足したり並べ替えたりしたら、そちらも直す。変えたら `npm run gen` → `npm run check` → `npm run record`。

## 守ること

型の README と同じ。特に次の2つ。

- **`src/game` は画面に触れない。** `Math.random` も時計も使わない
- **ルールやステージを意図して変えたら、動作記録を取り直す（`npm run record`）。**

## 公開

`main` に push すると、テスト → ビルド → GitHub Pages への公開まで自動で進む。
ゲームサイト（Poki・CrazyGames など）の広告 SDK は入っていない。差し込み口は `src/kit/platform/`。やり直しと次のステージの前に、区切りの広告を呼ぶ作りになっている。
